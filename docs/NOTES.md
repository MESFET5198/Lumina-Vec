# 实现说明与实验记录

README 只写用法。这里记录每一步的做法、为什么这样做，以及试过但放弃的方案。

## 处理流程

```
原图 ─► AI 去颗粒 ─► 均值漂移压平 ─► [线条层] ─► 明暗分层 ─► [打印清理] ─► vtracer 描摹 ─► [细节补回] ─► SVG
```

### AI 去颗粒（`denoise.py`）
先缩小 1/2，把颗粒平均掉，再用 Real-ESRGAN 动漫模型（`realesr-animevideov3`）放大 4 倍，重新生成锐利的线稿。有 CUDA 时自动用 GPU + fp16。

### 明暗分层（`bands.py`）
- **为什么需要**：vtracer 靠合并相似的相邻像素来长出区域。在平滑渐变上，这种合并会一路链式连下去，最后变成一整块纯色，调 `layer_difference` 也没用。所以必须先显式量化颜色。
- **调色板**：在 OKLab 色彩空间做 k-means，默认 112 色，明度权重 1.3、色度权重 2.0。另外为高对比像素单独分配 48 色，让嘴、鼻子这类小细节有属于自己的颜色。采样时压平颜色频率，面积小但颜色独特的区域（虹膜、腮红）也能分到色位。
- **平滑的色带边界**：渐变区像素的归属，由一张避开线稿的模糊图决定。离线稿越远，模糊半径越大（最大 σ=12），之后再做一次空间投票。色带边界因此是平滑的等值线，不是锯齿阶梯，下巴边缘也不会出现浅色晕边。
- **强边缘**（线稿、纹理）保留逐像素颜色。低对比度的小碎块并入邻区，高对比度的小块（高光、鼻点）保留。

### 线条层（`lines.py` + `ink.py`，仅 `shading` / `cel` 默认开启）
1. **哪里是线**：用 ControlNet `lineart_anime` 模型（`netG.pth`）判断，对颗粒不敏感。
2. **线的位置和宽度**：取原图中比周围暗的像素，并且只保留模型也认为是线的部分。模型单独认出的线，只在用来连接两段原图线条、补上缺口时才采用。模型会把虹膜、瞳孔的颜色分界也画成线，直接全部采用会多出原图没有的描边。
3. **重绘**：按"中心线 + 沿线平滑后的半宽"在 2 倍分辨率下重新画出。线宽不超过原图该处的宽度；高光（比周围亮的小块）不会被线条覆盖。
4. **颜色**：取中心线像素中较暗的一半。线条两侧的抗锯齿、色差红边青边都不会影响颜色。颜色相近的线合并为一组。
5. **线条下方的色块**：渐变图用 inpaint 平滑补色，平涂图用最近像素补色。最近像素补色在渐变图上会形成马赛克，平滑补色在平涂图上会生出色带，所以两者分开处理。

干净的厚涂、渐变插画（`shading-detail`）默认不开线条层：这类图原图的线条已经够干净，重绘反而会让睫毛、瞳孔这些地方变重。

### 平涂图（`cel`）
auto 会测量"平缓渐变像素占比"，低于 0.18 就判定为平涂图。平涂图不做渐变平滑（否则硬边高光外会多出一圈晕边），描摹用 cutout 共边模式，颜色数 48，不开细节补回层。

### 细节补回（`overlay.py`）
vtracer 会把很小的色簇并入邻区。一条 3 像素宽的嘴线，因为抗锯齿会被拆成约 10 种颜色，每种只有 1～3 个像素，必然被吞掉。所以按"和局部背景的对比度"重新找出这类小块，每块统一成一种颜色，单独描摹后叠在最上层。

### 打印清理（`--print-mm`）
- 设挤出线宽为 `min_px`。比它窄的颜色区域，按整块判断：如果跟两侧的颜色都明显不同，就是一条线（轮廓、发丝、色差边），整条保留并加粗；如果跟某一侧接近，说明只是抗锯齿过渡，整条并入邻区。判断前，颜色相近、首尾相连的几段会先合成一条。
- 宽区域里比线宽窄的细条交给邻区，图像保持完整覆盖，不会有空洞。
- 线条层的最小线宽等于挤出线宽，短于 4 倍线宽的线会被删掉。
- 描摹用 cutout 共边模式（stacked 模式下各形状单独拟合，接缝处会留下几千条细缝）。每个色块前加一条 `qq3d-gap-filler` 遮缝描边，格式与 Lumina 的过滤代码完全一致，导入 Lumina 时会被删掉，只用来让预览不出现缝隙。

## 试过但放弃的方案

| 方案 | 结果 |
|---|---|
| OKLab k-means + 众数滤波 + 无缝镶嵌 | 指标接近参考，但线稿碎裂 |
| 调低 `layer_difference` 来保留渐变 | 无效：渐变会被链式合并成一块 |
| 分层后做全局平滑 | 毛衣纹理、发丝被抹掉 |
| 只对低对比区平滑，色带边界取自均值漂移结果 | 色带边缘呈阶梯状或块状，打印不了 |
| 用固定 σ 模糊来决定色带 | 线稿渗进皮肤，下巴边缘出现晕边 |
| `filter_speckle=12` | 瞳孔高光、鼻子、嘴被删掉，改为 4 |
| 只按面积找五官 | 抗锯齿把嘴拆成多种颜色，找不到，改为按对比度检测 |
| 线条形状直接取原图暗像素 | 原图边缘本身就毛，描出来还是碎 |
| 线条直接采用模型画的线 | 粗线被画成两条细边；虹膜、瞳孔边界被多描一圈 |
| 线条颜色取全部像素的中位数 | 色差红边把黑线染成红色 |
| 线条颜色取最暗的 1/4 像素 | 所有线条整体偏深 |
| 打印模式逐像素判断窄条 | 一条线被切成断断续续的虚线 |
| 打印模式加粗所有细笔触 | 眼睛被糊成黑块，线条起疙瘩 |
| 线条下方用最近像素补色（渐变图） | 补出马赛克，高光被吞 |
| 高光检测用中值比较 | 线条旁边的普通肤色也被判成高光，留下细缝 |
| 色块逐区域填洞后模糊取等值线 | 区域之间出现白缝，细长区域消失 |
| 叠放描摹时给每个形状填洞 | 被包住的早画区域（如头发）被背景色盖掉，改为保留洞（evenodd） |
| 线条位置用"局部变暗"掩码 | 细淡轮廓和暗部阴影连成一片被当成色块丢掉，改用线稿模型自身的输出（阈值 0.15） |
| 线条去掉高光区域（膨胀后的 top-hat） | 白发旁边的线条全被吃掉 |
| 打印模式用新色块描摹 | 两条曲线描同一条边，留下不到 0.7 px 的细缝，打印模式继续用 vtracer cutout |

## 自研色块描摹（contour 分支）

色块层不再交给 vtracer：
1. 分层结果先做众数滤波（每种颜色的指示图高斯模糊后取最大），去掉单像素噪点和阶梯边。
2. 去掉细长区域（内切半宽 ≤ 1.2 px，即抗锯齿过渡带），交给最近的粗区域。
3. 按面积从大到小叠放。每个区域的形状 = 自身 + 所有之后要画的区域，所以每条可见边界只由一个形状决定，不会有缝；比它先画的区域留成洞。
4. 2 倍超采样后模糊，取亚像素等值线，拟合三次贝塞尔。

精灵图：色差 3.13（vtracer 3.09，参考 1.73），但边界是平滑曲线；配合新线条层（`--ink 1`）发丝和衣服轮廓是连续的细线。雷电图开线条层会丢眼睛高光，所以 `shading-detail` 仍默认不开线条。`--tracer vtracer` 可切回旧描摹。

## 线条层 v3 与精细模式（2026-11）

- 线稿模型对比（精灵图）：lineart_anime（现用）干净但漏淡线；lineart 写实偏脏；**manga_line（2017，MangaLineExtraction）线最实最连贯**；Anyline/MTEED 本质是边缘检测（双边、网格噪点），不适合当线稿。描线后独立线段：manga_line 674 段，lineart_anime 1578 段。
- 线稿模型要在原尺寸跑：模型直接在 2 倍尺寸下跑反而更碎（完整度 0.86，对比原尺寸跑完再放大 0.97）。
- 描线前的放大倍数（固定阈值后）：完整度 1× 0.83 → 1.5× 0.92 → 2× 0.97 → 3× 0.98 → 4× 0.97；节点密度 29 → 35 → 54 → 88 → 104。拐点 2×。
- 换用 Vecto 描色块没有提升（3.26 对 3.18）：瓶颈在分层图本身，不在拟合。
- v3：位置 = max(manga/0.6, anime/0.5)；粗细 = 原图墨色覆盖率，限制在模型中心线 1.6 px 内（宽的暗色区域留给色块层，眼睛不再糊成黑块）；2 倍放大后描轮廓；每段线取原图较暗的 35% 像素的均值作颜色。色块只在新线条下面补色。
- 花纹背景消失的原因：色带平滑（blur_sigma）把低对比细线当颗粒抹掉。原图、去颗粒、均值漂移之后花纹都还在。细纹保护：L 通道 7×7 黑/白顶帽 > 0.015 的像素不参与平滑。
- 小图（958 px）先缩小一半再去颗粒，发丝和花纹会丢。
- 色差（越低越好）：精灵 3.18 → 2.67；狐耳 3.43 → 2.90；花纹背景 3.04 → 2.10（Vecto 描线；自带描线 2.32），参考 1.98；雷电、旗袍、海边持平。
- 内存：manga_line 在 2.5k px 输入下超过 7 GB，所以两个线稿模型都限制在 1536 px 以内运行。

## 全局调色板实验（2026-11-04，`--palette N`，默认关闭）

- 参考 SVG：70～106 色，每色平均用在 16～51 个形状上，几乎没有只用一次的颜色，相邻调色板颜色色差约 2.3～3.4。
- 我们（白发图，精细模式）：1274 色，其中 1035 色只用一次。色块层 160 色，细节补回层加 294 色，线条层每段单独取色加 980 色。
- 实验：所有层统一成 96 色（按色差就近合并，合并后的颜色按面积加权），同色相邻区域自然合并。
  - 白发图：1274 → 96 色，路径 23355 → 17860（参考 5359）。
  - 精灵图：路径 7705 → 5881（参考 1550），色差 2.43 → 2.59。
  - 观感：整体略平静，但眼睛和"画出来的感觉"基本没变。颜色数不是主要原因，形状数量和边界画法才是。

## 区域取色实验（2026-11-04，`--region-color 1`，默认关闭）

- 肤色变白的原因：浅肤色和白色背景（OKLab 色差约 4）落进同一个颜色桶，桶颜色取全部像素的中位数，98% 是背景，于是整张脸被涂白（脸部纯白像素 1% → 55%）。不是"限色"本身，而是"同桶同色"。
- 改法：形状仍由分层决定，每块连通区域从 50% 缩小图取自己的颜色（均值；不足 40 px 的小区域用原尺寸），线条像素作为墙不让区域互连，相邻且色差 < 2 的区域合并，最后统一调色板（浅色加重色度权重，色差 > 2.5 的不强行合并）。
- 结果（白发图）：脸部纯白 54% → 0%，脸部平均色 253,251,250 → 248,246,240（原图 252,242,234，参考 247,239,228）。颜色 461，路径 21172（参考 5359）。眼睛基本不变。
- 结论：取色问题可以这样解决，但形状数量和眼睛不是取色决定的，是分层得到的形状本身太碎。
